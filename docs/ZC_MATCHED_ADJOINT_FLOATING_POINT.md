# Matched floating-point contract for direct ZC control

## Failure that exposed the mismatch

The original direct-control run paired the canonical controlled primal with
Tapenade's split reverse sweep.  Both execute the same prepared ZC equations,
but the canonical scientific objects were compiled with GNU Fortran `-O3`
whereas all derivative objects were compiled with `-O0`.  On member 403271,
phase-specific SQP reverse sweep 26 failed at model step 5.  The split-forward
state and the independently computed canonical state differed by 6.67188 in a
REAL coordinate (relative L2 difference 1.9567e-4) and by 5.10253 in a COMPLEX
coordinate (relative L2 difference 2.77628).  The bridge correctly rejected
the derivative rather than weakening its replay check.

The controlled iterate was close to the stopping threshold in the steady
atmosphere's convergence-feedback loop.  Small floating-point differences
between the optimized and unoptimized instruction streams selected different
iteration behavior, after which the states were genuinely different.  This
is a discrete-branch mismatch, not an acceptable roundoff discrepancy.

Compiling the generated reverse source with `-O3` does not solve the problem.
Tapenade's split forward sweep contains stack pushes and transformed control
flow, so it is not the same optimized instruction stream as the uninstrumented
canonical primal.  On an ordinary one-step state, an experimental `-O3`
reverse-forward build still differed from the canonical `-O3` primal by
6.02007e-5 in the largest REAL coordinate.  It therefore cannot guarantee the
same branch at a convergence threshold.

## Corrected build

The local builder creates `adjoint/controlled_reverse/build-v5` with three
executables made from one immutable run23-final3 source snapshot and one GNU
Fortran `-O0` floating-point contract:

- `zc_one_step_primal`
- `zc_one_step_tangent`
- `zc_one_step_adjoint`

Generated objects and executables are deliberately excluded from GitHub and
Zenodo. The public source and build recipe reconstruct this directory after
the user supplies the pinned upstream ZC source.

The unmodified prepared ZC primal source is recompiled at `-O0`; this is not a
port or a surrogate model.  Its one-step output and the adjoint's split-forward
output are bitwise identical on the controlled validation path.  A ten-step
tangent--adjoint audit over the phase-specific member-403271 control gave a
maximum relative dot-product defect of 2.87e-6, consistent with the model's
native float32 arithmetic.

## Relation to the released zc-v3 data

The processed zc-v3 data were generated by the canonical `-O3` executable.
The direct-control script therefore keeps two explicit roles:

1. It runs the canonical `-O3` zero path and requires bitwise agreement with
   the stored release input and ten-month Niño-3 target.
2. It runs an independent matched-`-O0` zero path, audits its branch tape and
   accumulated state discrepancy against the canonical path, and uses this
   matched path for both the controlled and paired zero outcomes in SQP.

Thus the reported intervention effect is never an `-O0` controlled trajectory
minus an `-O3` zero trajectory.  The compiler distinction is preserved in the
provenance and should be stated when describing the direct dynamical test.

Before the production solves, a complete forty-step comparison over all ten
fixed held-out members found zero differences among 1,200 branch-tape entries,
and passive state was bitwise identical. The largest standardized
release-coordinate difference was 3.11e-5, the largest AGOP-projection
difference was 2.29e-6, the largest release Niño-3 difference was 1.19e-7
degrees C, and the largest terminal Niño-3 difference was 1.43e-6 degrees C.
The aggregate build-audit workspace was temporary and is not part of the
public data deposit. Accepted steering reports retain the executable hashes,
matched-replay status, and case-level audits needed to validate the published
trajectories.

The largest absolute difference in any packed REAL coordinate was 2.06e-3,
although its relative state L2 difference was only 1.89e-7.  Packed native
coordinates have heterogeneous physical units and magnitudes.  The script's
1e-2 raw-coordinate guard is therefore only a coarse cross-compiler corruption
diagnostic; the relative-state and standardized scientific-coordinate checks
are the meaningful O0--O3 audits.  This has no effect on the matched O0
primal-versus-reverse check, which remains bitwise exact and is never relaxed.
